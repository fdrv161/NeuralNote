# Доступность NeuralNote для NVDA: памятка по обновлению

Ветка `a11y` в форке fdrv161/NeuralNote. Здесь записано, как переносить доступность
на новые версии автора (DamRsn/NeuralNote) и как быстро проверить, что ничего не сломалось.
Этот файл только для форка: в PR автору его не отправлять.

## 1. Как узнать о новой версии

На странице https://github.com/DamRsn/NeuralNote нажать Watch, выбрать Custom,
отметить Releases и нажать Apply. Тогда GitHub пришлёт письмо о каждом новом релизе.
Обновляться стоит только на релизы, а не на каждый коммит автора.

## 2. Как обновить (что сказать Claude)

Фраза: «Вышла новая версия NeuralNote, перенеси доступность, памятка в ACCESSIBILITY.md».

Порядок для Claude:

1. Удалённый репозиторий `upstream` (автор) подключён 11.10.2026, отправка в него отключена.
   Проверить: `git remote -v`. Если проект скачан заново и `upstream` нет:
   `git remote add upstream https://github.com/DamRsn/NeuralNote.git`,
   затем `git remote set-url --push upstream DISABLED`, чтобы туда нельзя было отправить.
2. `git fetch upstream`, посмотреть, что изменилось у автора: `git log --oneline a11y..upstream/main`
   и `git diff a11y...upstream/main --stat`. Коротко рассказать пользователю, что нового.
3. Слить без переписывания истории: `git merge upstream/main` в ветку `a11y`. Никаких rebase и force-push.
4. Конфликты решать так: берётся новый код автора, а доступность добавляется в него заново
   (имена, фокус, клавиши, озвучка). Список того, что где сделано, в разделе 3.
5. Проверить новые элементы интерфейса, которых раньше не было: у каждой кнопки, ползунка и поля
   должно быть имя (`setTitle`), до каждого можно дойти Tab, всё делается с клавиатуры.
6. Отправить в `origin a11y`, дождаться сборки GitHub Actions, если упала, исправить.
7. Попросить пользователя пройти контрольный список из раздела 4.
8. Если всё работает, выпустить релиз (раздел 5).

Ожидается у автора: ветка `upstream/resumable-transcriptions` (пауза и продолжение распознавания)
меняет `TranscriptionProgress`, `StatusBar`, `NnToolbar`, `VisualizationPanel` и `TranscriptionManager`.
После её выхода будут конфликты, а новой кнопке паузы нужны имя и озвучка состояния.
Сообщение «Transcription stopped» в `NeuralNoteMainView::timerCallback` тогда надо разделить
на «остановлено» и «на паузе».

## 3. Где лежит доступность

Общие помощники: `NeuralNote/Source/UI/NnAccessibility.h/.cpp`.

- `notifyToggleStateChanged`: сообщает NVDA о смене флажка или переключателя.
- `announce`: озвучка сообщения через UIA, где бы ни был фокус.
- `makeReadoutHandler`: элемент, который NVDA читает как текст, вычисляемый на лету.

Хрупкие места, проверять при каждом обновлении JUCE:

- В `NnAccessibility.cpp` объявлена внутренняя функция JUCE `sendAccessibilityPropertyChangedEvent`
  (из `juce_Accessibility_windows.cpp`). Если JUCE её переименует или изменит, сборка упадёт
  на линковке. Тогда найти новое имя в исходниках JUCE.
- `announce` приводит `getNativeImplementation()` к `IUnknown*`. Если JUCE поменяет устройство
  своего UIA-элемента, озвучка замолчит без ошибки сборки. Проверяется пунктами 4.6 и 4.8.
- `postAnnouncement` из JUCE не использовать: на Windows он говорит голосом SAPI мимо NVDA.

Что где сделано:

- Кнопки и ползунки: `NnFlatButton`, `NnFlatSlider` (фокус по Tab, озвучка переключателей).
- Имена элементов: `TopBar`, `NnToolbar`, `Sidebar`, `InstrumentStrip`, `NnGroupViewport`,
  `AudioRegion`, `MidiFileDrag`, `UpdateCheck`.
- Поле темпа: `NumericTextEditor.h` (остаётся полем ввода после включения).
- Выбор инструментов: `InstrumentMenu` (стрелки, пробел, Escape, отметки).
- Строка состояния и время: `StatusBar`, `TimeDisplay`.
- Прогресс распознавания и его озвучка: `TranscriptionProgress`, конец в `NeuralNoteMainView::timerCallback`.
- Панель моделей: `ModelDownloadPanel` (строки, стрелки, фокус при открытии, озвучка скачивания),
  возврат фокуса в `VisualizationPanel`.
- Горячие клавиши главного окна: `NeuralNoteMainView::keyPressed` (в том числе перемотка Ctrl+стрелки).
- Сборка: `.github/workflows/build.yml` (только Windows, только VST3, Vulkan) и описание релиза
  `.github/release-notes.md`. Автору не отправлять.

## 4. Контрольный список для проверки с NVDA

Проверять в REAPER с NVDA после каждого обновления. Рядом записано, что должен сказать NVDA.
Если что-то звучит иначе, записать, что именно сказал NVDA, и передать Claude.

1. Открыть окно плагина и пройти Tab по всему окну. У каждого элемента есть понятное имя,
   нет «кнопка» без названия и нет «unknown».
2. Поле Export tempo: NVDA говорит «Export tempo, редактор» и читает число.
3. Кнопка Add instruments, Enter: открывается список. Стрелки читают инструменты,
   пробел ставит и снимает отметку, NVDA говорит «отмечено» и «не отмечено». Escape закрывает список.
4. Кнопки Loop, Follow playhead, Mute input, пробелом: NVDA говорит новое состояние
   (например «нажато» и «не нажато»).
5. Tab до строки состояния: «Status: ...». Tab до времени: «Position 00:00.00 of ...».
6. Загрузить аудио, запустить распознавание. Звучит «Loading model» или «Transcribing»,
   проценты через каждые 10, в конце «Transcription finished, N notes».
7. Кнопка Model, Enter: фокус сам переходит на строку текущей модели. Стрелки вверх и вниз
   читают модели, у текущей «отмечено». Escape закрывает панель, фокус возвращается на Model.
8. Скачать маленькую модель: проценты по четвертям, в конце «Small model downloaded».
9. С загруженным аудио Ctrl+Стрелка вправо: «00:01.00». Ctrl+Shift+Стрелка влево
   возвращает в 00:00.00, повторное нажатие молчит.
10. Пробел запускает и останавливает воспроизведение, Shift+Пробел возвращает в начало.
11. Меню Settings открывается, подменю и отметки читаются.
12. Export MIDI out: открывается окно сохранения файла, после сохранения фокус возвращается в плагин.

## 5. Выпуск релиза

Сборки в Actions удаляются через 7 дней, релиз хранится всегда. Релиз создаётся сам, когда на
GitHub отправлен тег вида `v<версия автора>-a11y.<номер>`, например `v2.0.0-a11y.1`.
Версия автора — в первой строке `project(... VERSION ...)` файла `CMakeLists.txt`.
Номер после `a11y.` растёт с каждой нашей сборкой на той же версии автора и сбрасывается
на 1 при новой версии.

Команды (номер тега каждый раз новый):

1. `git -C "D:\a11y neuralnote\NeuralNote" tag v2.0.0-a11y.1 a11y`
2. `git -C "D:\a11y neuralnote\NeuralNote" push origin v2.0.0-a11y.1`

Через 20–30 минут релиз появится на https://github.com/fdrv161/NeuralNote/releases
Перед выпуском проверить, что `.github/release-notes.md` описывает то, что есть в сборке
(клавиши, изменения). Если шаг Publish release упал, прочитать его ошибку и исправить.
